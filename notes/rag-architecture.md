## 一、一句話核心觀念（TL;DR）

> **RAG（Retrieval-Augmented Generation，檢索增強生成）** 就像替聰明但記憶停留在過去的 LLM 舉辦一場「開書考（Open-Book Exam）」。模型不再硬背所有事實，而是在回答前先從外部知識庫檢索出最相關的段落（Context），再依據這些真實片段進行歸納與作答。

---

## 二、核心觀念拆解

### 卡片 1：為什麼需要 RAG？從「閉卷盲猜」到「開書考」
- **純 LLM 的兩大限制**：
  1. **知識時效凍結**：模型權重訓練完成後，無法得知公司內部最新規章或昨天發生的事件。
  2. **一本正經胡說八道（幻覺）**：遇到不確定的私有資訊時，語言模型仍會依據機率補完看似流暢卻錯誤的內容。
- **RAG vs. 微調（Fine-tuning）**：
  - 微調適合教模型「說話語氣與特定格式」，但更新事實成本極高。
  - RAG 只需更新外部文件與向量庫，即可即時更換事實來源，且能附上「資料出處（Citations）」。

### 卡片 2：RAG 的兩條核心管線（Indexing ＋ Retrieval & Generation）
- **離線索引管線（Indexing Pipeline）**：
  1. **Load（載入）**：解析 PDF、Markdown、Notion 或網頁文件。
  2. **Split / Chunking（文本切塊）**：將長文章切分成適合檢索的段落（通常搭配 `Chunk Overlap` 重疊視窗避免語意斷裂）。
  3. **Embed & Store（向量化存入）**：透過 Embedding Model 將文字轉為語意向量，存入向量資料庫（如 FAISS、Chroma、Qdrant）。
- **線上問答管線（Query Pipeline）**：
  1. **Query Embedding**：將使用者提問轉成同一個向量空間的座標。
  2. **Retrieve（Top-K 檢索）**：計算餘弦相似度（Cosine Similarity），撈出最相近的 `K` 個段落。
  3. **Augment & Generate**：將「系統提示詞 ＋ 檢索出的片段 ＋ 使用者問題」組裝成 Prompt，交由 LLM 產生有根據的回答。

### 卡片 3：決定 RAG 成敗的兩大超參數：Chunk Size 與 Top-K
- **Chunk Size（切塊大小）的權衡**：
  - **切太小（例如 80 字）**：語意支離破碎，雖然很容易命中關鍵字，但缺少前後文條件（例如漏掉「僅限 VIP 會員適用」這句例外條款）。
  - **切太大（例如 1,200 字）**：一個區塊混雜多個無關主題，向量特徵被稀釋（Dilution），反而讓真正相關的句子相似度下降，還可能塞入過多雜訊。
  - **實務黃金區間**：常見中文文件建議以 **300～500 字**搭配 **10%～20% Overlap** 起步，再依文件結構微調。
- **Top-K（取回片段數）的權衡**：
  - `K=1` 容易漏掉跨段落的分散線索；`K=5` 以上會增加 Token 成本並可能觸發「迷失在中間（Lost in the Middle）」效應，導致模型注意力被雜訊分散。

### ⚠️ 常見誤區與地雷提醒（Pitfall Alert）
- **誤區：「只要用了 RAG，模型就不會產生幻覺了。」**
- **真相**：Garbage In, Garbage Out（垃圾進、垃圾出）。如果切塊切斷了關鍵數字、或相似度檢索撈回了過時的舊文件，LLM 依然會用非常流暢的語氣，忠實地念出錯誤的檢索內容；因此 **「檢索評估（Retrieval Evaluation）」** 往往比調 Prompt 更重要。

## 三、互動實驗室規格（Interactive Lab Spec）

- **實驗室名稱**：RAG 檢索與 Chunk Size 參數模擬器
- **教學目的**：讓學習者親手調整 `Chunk Size` 與 `Top-K`，直接觀察相同知識庫文件在不同切塊粒度下，對相似度排序、Context 雜訊比例與最終回答品質的影響。
- **控制元件（Inputs）**：
  - 提問情境切換按鈕（3 題真實情境：「遠距工作申請規定為何？」「出差高鐵票報帳上限是多少？」「實習生試用期滿有特休嗎？」）
  - Chunk Size 三段切換鈕：`過小（80 字碎片）`、`適中（350 字＋重疊）`、`過大（1,000 字混雜）`
  - Top-K 滑桿：`K = 1` 到 `K = 3`
- **視覺化輸出（Outputs）**：
  - 顯示實際被切割並檢索出的 Chunk 卡片清單、模擬相似度分數（Cosine Score）與標示為「精準證據 / 語意不完整 / 含雜訊」的狀態標籤。
  - 模擬組裝後的 LLM 最終回答卡片，以及「回答完整度與可信度評級」。

## 四、隨堂自我檢測（3 題單選題）

### Q1：在 RAG 系統中，為何通常需要為切分後的文本塊設定「Chunk Overlap（重疊區間）」？
- A. 為了讓向量資料庫佔用更多硬碟空間以提升效能
- B. 避免關鍵句或前後因果關係剛好在切分邊界被截斷，保留跨段語意連貫
- C. 因為 Embedding 模型規定相鄰兩個句子必須完全相同才能運算
- D. 讓 LLM 在生成時可以重複輸出同一段文字兩次
- **正解**：`B`
- **詳解**：固定長度切分很常把「條件」與「結論」切成兩塊，加入 10%～20% 的 Overlap 能確保邊界處的完整語意同時保留在相鄰兩個 Chunk 中。

### Q2：當團隊將文件 Chunk Size 設得「過大（例如整篇 2,000 字法規塞成單一向量）」時，最容易發生什麼問題？
- A. 單一向量必須壓縮過多不同主題，導致目標句子的語意訊號被稀釋、檢索精度下降
- B. 文件切分速度會變慢十倍且無法存入向量資料庫
- C. LLM 會自動拒絕對超過 500 字的 Context 進行閱讀
- D. Cosine Similarity 分數永遠會變成負數
- **正解**：`A`
- **詳解**：Embedding 向量是固定維度的語意摘要。區塊內包含越多無關段落，向量就越像「整篇的平均語意」，反而使特定問題難以精準匹配，並把大量雜訊送進 Prompt。

### Q3：如果公司每天都會更新數十份產品售價表與客服 QA，應該優先採用哪種策略讓 AI 回答最新資訊？
- A. 每天晚上重新執行一次全模型預訓練（Pre-training）
- B. 把所有售價表硬寫進 System Prompt，直到超過視窗上限
- C. 採用 RAG 架構，只更新向量資料庫中異動的文件切片並於回答時附上來源出處
- D. 調整模型解碼溫度（Temperature = 1.5）讓模型自行推估最新價格
- **正解**：`C`
- **詳解**：RAG 的核心優勢就是將「推理能力（模型）」與「動態知識（外部資料庫）」解耦，適合高頻率異動的事實資料更新。
