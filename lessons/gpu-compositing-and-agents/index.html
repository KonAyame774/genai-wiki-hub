GPU 合成圖層效能瓶頸與 AGENTS.md 規範

漂亮不能以卡頓為代價——剖析 backdrop-filter 的 GPU 重繪成本，並把光學預算與設計規則寫進 AGENTS.md。

TL;DR 一句話核心觀念

backdrop-filter 是瀏覽器效能代價最高的 CSS 屬性之一——它會強迫瀏覽器開闢獨立的 GPU 合成圖層，並在底層內容捲動或改變時不斷重繪。想讓 AI 長期幫你擴充毛玻璃網站而不失控掉幀，就必須把 圖層數量上限、嵌套禁忌與標準 .glass-panel 寫法 寫進 AGENTS.md。

🧩 核心觀念拆解

TECHNIQUE 01

為何 backdrop-filter 會拖慢低階裝置？

  • GPU 即時擷取循環：每個模糊容器都必須先繪製後方畫面 → 複製到 GPU 紋理緩衝 → 執行二維卷積模糊與彩度計算 → 再合成前景。
  • 雙重災難：畫面同時堆疊過多層磨砂容器，或在捲動視差頁面中大面積使用，會讓手機幀率急劇下滑。
核心瓶頸：背景每移動 1px，所有覆蓋在其上方的模糊圖層都要於 16.6ms 內重算！
TECHNIQUE 02

外玻璃、內半透實底的架構解法

  • 節制主玻璃層：僅在最外層主卡片與 Sticky Topbar 啟用 blur(20px) saturate(190%)。
  • 次級元素零模糊：主卡片內部的標籤、表格與輸入框改用 rgba(255, 255, 255, 0.58) 半透明實底，既保層次又不耗 GPU 紋理填充率。
實戰成效：本知識庫首頁與所有單元頁皆採「外玻璃＋內實透」架構，確保行動裝置順滑捲動。
TECHNIQUE 03

把光學設計系統寫入 AGENTS.md

  • Vibe Coding 的問題：沒有規範時，AI 下次新增頁面可能擅自改掉飽和度補償、忘記 ::before 50% 切線，或把卡片嵌套三層模糊。
  • AGENTS.md 合約化：直接鎖死 .glass-panel 基準程式碼、五大技巧、SVG 雜訊與禁止嵌套規則，讓 AI 長期穩定產出。
搭配檔案：AGENTS.md（憲法）＋ notes/_template.md（SOP）＋ NOTES.md（白板）。

⚠️ 常見誤區：我的電腦跑 120Hz 很順，所以頁面塞滿動畫毛玻璃沒關係？

中低階行動裝置的 GPU 紋理填充率有限。只要螢幕可視區內同時重疊超過 5～6 層 backdrop-filter 且底層背景持續執行視差動畫，手機畫面就會瞬間跌破 25fps，甚至造成閃爍或系統強制關閉模糊濾鏡。

📝 隨堂自我檢測（點擊選項立即批改）

Q1. 為何在行動裝置畫面上堆疊過多層 backdrop-filter 或搭配視差捲動時，畫面幀率（FPS）容易明顯下滑？
✅ 解析（正解：A）：背景模糊是相依於下方像素的即時後處理濾鏡；背景每動一幀，覆蓋在上的模糊層都要重新採樣運算。
Q2. 若想在已套用 backdrop-filter 的 .glass-panel 卡片內部再放一個提示框或標籤，最符合效能預算的做法為何？
✅ 解析（正解：B）：外層主卡片負責模糊折射，內層元素採用高通透純色半透明背景即可保持視覺和諧，且零額外 GPU 模糊成本。
Q3. 將 .glass-panel 標準程式碼與 GPU 圖層限制寫入 AGENTS.md，對長期專案擴充的最大價值為何？
✅ 解析（正解：A）：這正是 Agentic Work 的核心價值——把設計美學與工程紀律寫進專案憲法，讓任何 AI 代理都能穩定擴充網站。
