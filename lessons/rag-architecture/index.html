RAG 檢索增強生成原理與實務

讓大型語言模型在回答前先「翻書找證據」，大幅降低幻覺並即時接軌企業或個人知識庫。

TL;DR 一句話核心觀念

RAG（Retrieval-Augmented Generation） 就像替聰明但記憶停留在過去的 LLM 舉辦一場「開書考（Open-Book Exam）」。模型不再硬背所有事實，而是在回答前先從外部向量資料庫檢索最相關的段落（Context），再依據這些真實片段進行歸納與作答。

🧩 核心觀念拆解

CONCEPT 01

為什麼需要 RAG？從「閉卷盲猜」到「開書考」

  • 知識時效凍結：預訓練模型無法得知公司今天早上才頒布的最新規章或內部報價單。
  • 降低語言幻覺：遇到不確定的私有資訊時，純 LLM 會依機率接龍出流暢卻完全虛構的答案。
  • 可追溯出處：RAG 能把參考的文件編號或段落附上（Citations），方便人類覆核。
微調 vs. RAG：微調適合教「說話口吻與特定格式」；動態變動的事實知識一律優先交給 RAG。
CONCEPT 02

兩條核心管線：離線索引 vs. 線上檢索

  • 離線索引（Indexing）：載入文件（Load）→ 文本切塊（Chunking）→ 轉成語意向量（Embedding）→ 存入向量資料庫。
  • 線上問答（Query）：把問題也轉為向量 → 計算餘弦相似度撈出 Top-K 片段 → 將片段塞入 Prompt 交由 LLM 作答。
關鍵公式：Prompt = System + Retrieved Chunks (Top-K) + Question
CONCEPT 03

成敗關鍵超參數：Chunk Size 與 Top-K

  • 切太小（如 80 字）：語意支離破碎，容易把「條件限制」跟「主結論」切成兩半。
  • 切太大（如 1,000 字）：混雜無關段落，關鍵句向量被稀釋，檢索分數反而下降。
  • 黃金起手式：中文文件建議 300～500 字搭配 10%～20% 重疊（Overlap），防止邊界語意斷裂。
Top-K 建議：通常取 K = 2～4；塞入過多無關片段會觸發「迷失在中間（Lost in the Middle）」效應。

⚠️ 常見誤區與地雷提醒：用了 RAG 就不會有幻覺了嗎？

真相是 Garbage In, Garbage Out（垃圾進、垃圾出）。如果文本切塊切斷了關鍵數字（例如漏掉「僅限正職適用」這行例外條款），或向量檢索撈回已經過時的舊公告，LLM 依然會用非常自信流暢的語氣，忠實地念出錯誤的檢索內容。因此 檢索品質評估 往往比修改 Prompt 更關鍵！

📝 隨堂自我檢測（點擊選項立即批改）

Q1. 在 RAG 系統中，為何通常需要為切分後的文本塊設定「Chunk Overlap（重疊區間）」？
✅ 解析（正解：B）：固定長度切分經常把「前提條件」與「最終結論」切成兩塊，加入 10%～20% 的 Overlap 能確保邊界處的完整語意同時保留在相鄰兩個 Chunk 中。
Q2. 當團隊將文件 Chunk Size 設得「過大（例如整篇 2,000 字法規塞成單一向量）」時，最容易發生什麼問題？
✅ 解析（正解：A）：Embedding 向量是固定維度的語意摘要。區塊內包含越多無關主題，向量就越像「平均雜訊」，使特定細節問題難以精準命中。
Q3. 如果公司每天都會更新數十份產品售價表與客服 QA，應該優先採用哪種策略讓 AI 回答最新資訊？
✅ 解析（正解：C）：RAG 的核心優勢就是將「推理能力（模型）」與「動態知識（外部資料庫）」解耦，最適合高頻異動的事實資料更新。
