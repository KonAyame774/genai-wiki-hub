換你當老闆！AGENTS.md 與 AI 協作工作流

從一次性的 Vibe Coding 進化到 Agentic Work——用專案憲法讓 AI 成為可長期共事的團隊成員。

TL;DR 一句話核心觀念

AI Agent ＝ Model（大腦）＋ Harness（工作環境與規則系統）。Vibe Coding 只關心「這次把一個網頁生出來」；而真正的 Agentic Work 是你退居老闆與架構師角色，透過 AGENTS.md（專案憲法）、NOTES.md（現況白板）與 notes/_template.md（SOP 範本），讓任何新開啟的 AI 對話都能立刻接手並穩定擴充整個專案。

🧩 核心觀念拆解

CONCEPT 01

Vibe Coding vs. Agentic Work 的本質差異

  • Vibe Coding（單次抽卡）：在聊天視窗憑感覺生出單一網頁；下次想加第 2 頁時忘記上次的色票與結構，AI 只好重新亂猜，整個網站越改越歪。
  • Agentic Work（系統化交辦）：把不可忘記的規則寫進 Git Repo 的 Markdown 規範檔裡，換電腦、開新視窗或換工具都不會失憶。
身份轉換：你不再只是「寫 Prompt 的操作員」，而是設計工作制度（Harness）的老闆。
CONCEPT 02

長期協作環境的「四大核心檔案」

  • AGENTS.md / CLAUDE.md：專案憲法，定義視覺系統、檔案結構、命名慣例與禁令。
  • notes/_template.md：內容先行的 SOP 範本，強制先定文字稿再轉 HTML。
  • NOTES.md：現況白板，記錄做到哪與待擴充 Backlog，每次收尾必更新。
  • log.md：決策歷史日誌（只增不刪），記錄「為什麼過去這樣決定」。
本專案本身就是活範例：你可以打開根目錄對應檔案對照本頁設計！
CONCEPT 03

寫出「AI 照著做不會歪」的 AGENTS.md 心法

  • 給具體數值，拒絕抽象形容詞：不要寫「配色要溫暖有質感」，要寫「背景固定 #FAF7F2，卡片邊框 2px solid #1E293B」。
  • 明確寫出標準流程（Workflow）：把「新增一頁」拆成 4 個可檢查的動作（原稿 → 網頁 → 首頁卡片 → 更新白板）。
  • 列出不可觸犯的禁令（Don'ts）：例如嚴禁使用 / 開頭根路徑，確保 GitHub Pages 子目錄不破連結。
判斷標準：把這份檔案交給一位全新的 AI 員工，它不問你問題也能做出 90 分成品嗎？

⚠️ 常見誤區與地雷提醒：每次把要求複製貼上到聊天室不就好了嗎？

當專案超過 3 個頁面時，靠手動複製 Prompt 一定會失控。你可能在開發 Unit 03 時臨時決定「加上手機響應式邊距」或「新增分類篩選標籤」，如果沒有把決策寫回版本庫裡的 AGENTS.md 與 NOTES.md，下個月重開對話時 AI 仍會照舊規則生成，留下難以維護的技術債。

Q1. 在「AI Agent ＝ Model ＋ Harness」的公式中，專案裡的 AGENTS.md 與目錄結構規範屬於哪一個部分？
✅ 解析（正解：B）：AGENTS.md、範本、白板與目錄慣例共同構成了 AI 工作的 Harness（工作制度），即使切換不同模型也能維持一致品質。
Q2. 為什麼本專案的 AGENTS.md 會同時規範 NOTES.md（現況白板）與 log.md（變更紀錄）的分工？
✅ 解析（正解：A）：AI 對話視窗是暫時性的；將專案狀態寫進 NOTES.md、將決策演進記進 log.md，才能讓下一個 AI Session 無縫接手。
Q3. 下列哪一種寫法最適合放進 AGENTS.md 來規範網頁的視覺風格？
✅ 解析（正解：C）：對 AI 而言，越具體、可驗證的數值（Hex 色碼、字體名稱、檔案路徑與必經步驟）越能消除歧義，確保跨頁面產出的一致性。
