Reflection 反思型 Agent 架構與設計

告別「一次生成就交卷」，透過 Drafter → Critic → Refiner 自我審查迴圈大幅拉升輸出品質。

TL;DR 一句話核心觀念

Reflection（反思型 Agent） 的核心精神是「不讓模型一次講完就交差」。透過將任務拆解為 初稿生成（Drafter）→ 批判審查（Critic / Reflector）→ 迭代重構（Refiner） 三個角色分工，讓 AI 先以嚴格評分標準（Rubric）揪出自己初稿的盲點，再對症下藥改寫出接近人類專家水準的成品。

🧩 核心觀念拆解

CONCEPT 01

為什麼 Zero-Shot 一次生成容易平庸？

  • 自回歸生成的慣性（快思考）：LLM 一字一字往後預測，開頭若漏了條件或語氣太衝，後文只會順著錯誤脈絡繼續寫下去，無法回頭塗改。
  • 改考卷比寫考卷容易：當同一個模型被指定扮演「挑剔審稿者」時，注意力會聚焦於找漏洞、抓邊界條件與語氣風險，準確率遠高於盲寫。
類比：如同人類寫重要信件時，寫完草稿放十分鐘再自己當讀者抓錯字與語病。
CONCEPT 02

Reflection 三階段標準角色分工

  • ① Drafter（初稿生成器）：快速完成「從 0 到 1」的 65 分完整草稿，不求一次完美。
  • ② Critic / Reflector（專家審查器）：禁止客套，依 Rubric 評分（1～10 分）並列出 2～4 條具體修改建議。
  • ③ Refiner（迭代重構器）：同時讀入「原始目標 ＋ 初稿 ＋ 審查報告」，逐條修復瑕疵產出定稿。
資料流：Draft → Critique(Rubric) → Refine(Goal, Draft, Critique)
CONCEPT 03

設計高品質 Rubric 評分表的三要素

  • 維度明確不重疊：例如拆為「目標達成度」、「專業與語氣」、「風險防護」三個軸向。
  • 強制量化與引證：要求為每個維度打分，並引用初稿裡的具體句子解釋為何扣分。
  • 明確停止條件（Stopping Criterion）：限制最多迭代 1～2 輪，或分數達門檻（如總分 ≥ 27/30）即收手。
關鍵提醒：只寫「請幫我改得更好」會讓 AI 只換同義詞；唯有具體 Rubric 能逼出實質改進。

⚠️ 常見誤區與地雷提醒：反思越多輪，品質就越高嗎？

不一定！如果 Critic 沒有具體的檢查清單或外部驗證（例如程式單元測試結果），讓模型無限自我反思 4～5 輪，反而會出現 「過度修飾（Over-refinement）」：字數越來越臃腫、充滿空洞客套話，甚至把原本精準的細節改偏。實務上 1～2 輪高品質反思 通常已是性價比最佳點。

📝 隨堂自我檢測（點擊選項立即批改）

Q1. 為何在實作 Reflection Agent 時，必須給 Critic（審查者）設計明確的 Rubric 評分維度？
✅ 解析（正解：B）：缺乏明確評估標準時，LLM 的自我修正經常變成表面換字。具體的 Rubric 維度才能引導 Critic 提出真正有價值的修正點。
Q2. 在典型的三階段 Reflection 架構中，Stage 3（Refiner）的輸入 Context 通常需要包含哪些要素？
✅ 解析（正解：C）：Refiner 必須同時掌握「原始目標（不偏題）」、「初稿（保留正確內容）」與「Critic 建議（精準修補瑕疵）」。
Q3. 下列哪一項做法最能避免 Reflection Agent 陷入「無止盡微調與過度官腔化」的陷阱？
✅ 解析（正解：A）：設定最大迭代次數或達標門檻，能防止模型為了「為改而改」而把原本簡潔實用的回答改得過度冗長。
